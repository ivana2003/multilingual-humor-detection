# Reproducibility report

## Executive assessment

The final paper is the canonical experimental specification. The supplied ZIP provides useful fragments and many candidate result tables, but it is not a complete, internally consistent provenance package. The cleaned repository therefore implements the paper's intended methods while keeping archive evidence separate from both the published table and future reproduced outputs.

## CoMB versus ColBERT

The archive's earliest split code loads `CreativeLang/ColBERT_Humor_Detection`, creates an 80/20 split, and stores identifiers under a ColBERT name. ColBERT is not CoMB and is not accepted as a substitute.

Later English scripts are named for CoMB and expect `data/comb_data.csv` plus a `CoMB` entry in split metadata. Neither the CSV nor a CoMB split manifest is present. There is no acquisition, aggregation, normalization, or hashing step that demonstrates how the paper's 45,488 CoMB examples were obtained.
The root-level `results/transformers_cv_and_test.csv` is explicitly labeled `ColBERT Humor EN` and is therefore not used as evidence for CoMB. Only the later `comb/results/transformers_comb.csv` files are treated as candidate CoMB result evidence.

**Conclusion:** CoMB-specific model code fragments and result CSVs were found, but the actual CoMB preparation pipeline was not found. The English results cannot be reproduced from the archive alone.

## Split protocol

The paper specifies stratified 70/10/20 train/validation/test splits. The only reusable manifest in the archive covers ColBERT and Spanish and was produced by legacy 80/20 code. Other scripts create splits internally in several different ways, often without durable identifiers or hashes.

The cleaned implementation uses one deterministic split module, seed 42, unique IDs, full coverage, disjointness checks, per-split class summaries, and SHA-256 metadata. Seed 42 is an explicit reconstruction choice because the paper does not print a seed and no single paper-wide seed could be established from the archive.

## Dataset provenance and label concerns

- **English:** CoMB raw data and preparation are absent.
- **Spanish:** old scripts refer to the Hugging Face name `mrm8488/CHISTES_spanish_jokes`, while the paper cites Martínez's `liopic/chistes-nlp` repository. Similar size/language is insufficient proof of byte-level or row-level equivalence. No archived hash or provenance record links them conclusively. Some legacy code also expects inconsistent column names, and one split script fabricates alternating labels when a label field is absent; that behavior is excluded.
- **Portuguese, Chinese, Hindi-English:** the archive contains loader logic and results but no raw snapshots, immutable source revisions, or complete license records.

The new data preparer will not download or invent data. It validates the exact paper totals and rounded class distributions after users obtain files from official sources.

## Table 2 traceability

The detailed cell-level audit is in `results/archive_evidence/table2_traceability.csv`. Of 39 non-empty Table 2 cells:

- 22 have an archive held-out-test value that directly rounds to the published value;
- 2 additional English traditional-ML cells numerically match but were generated by code that caps the test set at 500 records;
- 3 cells match only cross-validation or prompt-variant means rather than held-out test metrics;
- 3 are close test values that do not round to the published number;
- 9 remain unresolved because the closest archive results differ materially or suggest a possible row/model swap.

This count concerns numerical traceability only. Even “traceable” cells may still lack complete data/split provenance.

Notable discrepancies:

- DeBERTa's paper value `0.966` matches an archive cross-validation mean (`0.966175`), while the test value in the same file is approximately `0.960`.
- Spanish GPT-4o-mini values `0.402` and `0.436` match prompt-variant CV means, not clear held-out-test records using the Appendix A.4 templates.
- BETO `0.649`, Hindi-English LR `0.524`, Portuguese SVM `0.843`, Qwen English zero-shot `0.770`, and Qwen Chinese zero-shot `0.776` lack supporting held-out values in the archive.
- Chinese LR/SVM rows in the archive are near the two paper values in the opposite order, but this cannot be silently corrected.
- BERTimbau, MuRIL, and Hindi-English Qwen zero-shot have small but real rounding mismatches.

No published value was changed to fit the archive, and no archive value was relabeled as reproduced.

## Traditional ML reconstruction

The canonical pipeline implements only:

- TF-IDF word unigrams and bigrams;
- `min_df=2`;
- LR and linear SVM;
- stratified 5-fold cross-validation over `C = 0.1, 1, 10`;
- final fit on training plus validation;
- held-out test macro-F1.

Legacy max-feature variants, RBF branches, and “ours/Gorecki” labels are excluded.

## Transformer reconstruction

Only the six identities reported in Appendix A.2 are exposed. Shared settings are centralized in YAML. The paper reports a warmup range of 6–10% rather than one exact value; the default configuration uses 8% and preserves the published range in metadata. The script trains on the training split, uses validation for checkpoint selection, and reports one held-out-test macro-F1. It does not run on import and does not download a model unless the command is explicitly executed.

The Chinese config preserves the paper identity `bert-base-chinese` and uses the current canonical Hugging Face alias `google-bert/bert-base-chinese`.

## LLM reconstruction

The two templates in `src/humor_detection/prompts.py` are transcribed from Appendix A.4. Few-shot prompts use exactly five examples from each class, selected only from the training split. The paper does not specify the exact ordering/serialization of examples; the repository uses repeated `Text:` and `Classification:` fields and records this implementation choice.

Qwen is implemented with deterministic greedy generation (`do_sample=False`). The paper simultaneously reports greedy decoding and temperature 0.1. Since sampling temperature has no effect under deterministic greedy decoding, the repository records the published temperature as metadata but does not pretend it changes generation.

GPT-4o-mini is not called during construction or validation. Execution requires an environment credential and an explicit paid-call authorization flag. Prediction caches are append-only JSONL and keyed by model plus prompt hash.

## Reported and reproduced results

- `results/paper/table2_reported.csv` is immutable reference data transcribed from the paper.
- `results/archive_evidence/` records historical traceability and is neither reported nor reproduced output.
- `results/reproduced/` is reserved for new executions.

The aggregator reads only completed `result.json` files marked `held_out_test`, selects `metrics.test.macro_f1`, and refuses duplicate model/language cells.

## Missing artifacts and blockers

1. Raw datasets and immutable source revisions.
2. A verified CoMB acquisition/preparation pipeline and manifest.
3. Proof that the old Hugging Face Spanish copy is exactly the Martínez dataset used in the paper.
4. Confirmed redistribution/license scope for each dataset.
5. A paper-wide original random seed, if seed 42 was not actually used, and the exact per-run warmup ratio within the reported 6–10% range.
6. Held-out-test evidence for all unresolved Table 2 cells.
7. Exact few-shot example IDs and their ordering for historical LLM runs.
8. Final code-license choice by the authors.

Until those are resolved, the repository supports a faithful re-execution of the stated method after data preparation, but it cannot establish bit-for-bit reproduction of every published number.
